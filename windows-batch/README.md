# 星辰Dola 批量视频生成

把「上传图 → 选视频生成 → 开 30 秒 → 选 Seedance 2.5 → 选 9:16 → 粘提示词 → 发送」
这一串重复操作自动化，跑完整个队列，账号额度用完自动换下一个。

## 为什么是独立工具，而不是加进创作台

创作台 2.6 的 exe 里有防篡改保护：

```
IntegrityGuard    EnsureUntampered    VerifySignature    ShowTamperMessage
```

而且那些注入脚本是内嵌在 exe 里运行时解压的，不是磁盘上可编辑的文件。
往里加东西会触发篡改检测，而绕过防篡改不在可做的范围内。

所以这个工具**完全跑在创作台外面，一个字节都不碰它**。用你的账号 Cookie 直接开
浏览器干活，和创作台互不干扰，两边可以同时开着。

## 怎么用

### 1. 装 Node.js

https://nodejs.org ，18 以上版本，一路下一步。

### 2. 填账号

把 `accounts.json.example` 复制一份改名成 `accounts.json`，填入每个账号的 Cookie：

```json
[
  { "id": "dola-1", "name": "Dola Cookie 1", "cookie": "你的cookie", "proxy": "" },
  { "id": "dola-2", "name": "Dola Cookie 2", "cookie": "你的cookie", "proxy": "" }
]
```

Cookie 三种格式都认：请求头原文（`a=1; b=2`）、Cookie-Editor 导出的 JSON 数组、
Netscape `cookies.txt`。和你往创作台里导入时用的是同一份东西。

### 3. 先校准一次（重要）

```
双击  校准.bat
```

会用第一个账号打开页面，把真实的控件结构导出成 `probe-report.json` 和两张截图。

**把这三个文件发回给 Claude**，就能把选择器钉死。这一步的原因见下面「已知事项」。

### 4. 放任务

按 `queue/_怎么放任务.md` 的约定，一个任务一个文件夹。

### 5. 开跑

```
双击  开始批量.bat
```

想先检查队列有没有问题，不真的生成：

```
开始批量.bat --dry-run
```

## 配置

都在 `config.json` 里：

| 项 | 默认 | 说明 |
|---|---|---|
| 提示词前缀 | `不要让我进行任何二次确定，按照你的理解直接生成视频：` | 自动加在每条提示词开头 |
| 模型 | `2.5` | Seedance 2.5 |
| 时长秒 | `30` | 30 秒 |
| 比例 | `9:16` | 竖屏 |
| 每个账号生成条数 | `2` | 每号每天跑几条 |
| 提交间隔 | 45–90 秒随机 | 两条之间的等待，别调太短 |
| headless | `false` | 第一次跑建议开着窗口看 |

## 30 秒是怎么开的

Dola 原生时长菜单只有 5/10/15 秒。创作台的「30 秒」按钮实际是写了两个
localStorage 开关，再在发请求时把 `ability_type:17` 节点里的
`ability_param.duration` 改写成 30。

本工具直接复用了创作台的原版脚本 `dola-15s-dom-request-hook.js`（一行未改，
在 `vendor/` 里），在页面加载前注入，所以机制和你现在用的完全一致。

参考图上传同理，复用原版 `dola-reference-materials.js`，走 Dola 自己的上传管线，
没有逆向它的接口。

## 额度与断点

- 每个账号每天的次数记在 `state.json`，**按本地日期归零**，跨天自动重置。
- 服务端说额度没了（`今天的生成次数已经达到上限` / `视频生成额度不足`），
  立即把该账号标记为用满并换下一个 —— 错误识别逻辑和创作台自带的
  `ba_curl_submit.py` 对齐。
- 成功的任务文件夹移走，所以中断后重跑不会重复生成。

## 已知事项

**这个工具是在无法访问 dola.com 的环境里写的，没有对着真实站点跑过。**

能确定的部分：
- 30 秒开关的键名、`ability_param.duration` 的改写路径、参考图上传管线 —— 都来自
  创作台原版脚本，是确定的。
- 额度/限流/登录失效的判定文案，来自原版 `ba_curl_submit.py`，是确定的。

需要校准的部分：
- 模型、时长、比例三个下拉控件的具体选择器和菜单项文本。代码里按原版脚本出现过的
  `data-input-engine-actionbar-control-key` 推导，并做了多级降级（精确 key → 模糊
  key → 文本特征匹配），但没验证过。
- 提示词输入框、文件 input、发送按钮同理。

**所以请先跑一次 `校准.bat`。** 导出的 `probe-report.json` 里有全部真实结构，
填进 `config.json` 的 `_选择器` 段即可覆盖内置猜测；或者把文件发回来我来填。

跑的时候日志会打印每个动作命中了哪条策略，比如
`模型控件定位方式：[data-input-engine-actionbar-control-key="video-model"]`，
出问题时对着日志看就知道卡在哪一步。

## 风险提醒

批量自动提交有被平台风控的可能。默认 45–90 秒的随机间隔是保守值，
不建议调低。每个账号只跑 2 条也是你自己定的额度上限，别硬超。
