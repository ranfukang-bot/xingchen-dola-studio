# 星辰Dola 批量生成（Chrome 扩展）

在 dola.com 页面里直接批量生成视频：自动选 2.5 / 30 秒 / 9:16、自动传参考图、
自动在提示词前面加那句固定的话、自动换账号、自动把**无水印**成片下载回来。

你只做两件事：**选队列文件夹、点开始。**

---

## 为什么做成扩展，而不是软件 / 油猴 / 网站

| | 能不能用 | 为什么 |
|---|---|---|
| 独立软件（Playwright 自动化浏览器） | ❌ | 一启动就带着「我是机器人」的特征，**每次打开都弹滑块** |
| 网站 | ❌ | 浏览器铁律：你的网站碰不到 dola.com 的登录态，什么也干不了 |
| 油猴脚本 | 🔸 | 能躲滑块（跑在你真实浏览器里），但**没法切换账号** |
| **Chrome 扩展** | ✅ | 油猴能干的都能干，**外加自动换账号 + 正经下载** |

关键在于：扩展跑在**你自己那个真实的 Chrome** 里，不是伪装的自动化浏览器。
所以和你用创作台一样——**有效 Cookie 直接已登录，不弹滑块**。

换账号的原理也和创作台完全一致：同一个真实浏览器，只是把 dola.com 的 Cookie
换成下一个账号的。浏览器本身没变，所以不会被当成机器人。

> 佐证：创作台那个「无水印」功能本身就是一个 Chrome 扩展。这条路在 dola 上
> 早就被验证能走通，不是瞎猜。

## 安装（Mac / Windows 一样，不用编译）

1. 打开 Chrome，地址栏输入 `chrome://extensions`
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**，选中本仓库的 `chrome-extension` 文件夹
4. 打开 https://www.dola.com/chat ，页面右边会出现一个竖排的 **批量** 按钮

就这四步。不用装 Node、不用编译、不用签名、不用过 Gatekeeper。

> 需要 Chrome 111 以上（2023 年 3 月之后的版本都行）。

## 用法

点右边「批量」按钮展开面板：

**1 · 队列文件夹**
点一下，选中装着任务的那个总文件夹。结构是：

```
我的队列/
  001-口红/
    prompt.txt        ← 这条的提示词
    1.jpg  2.jpg      ← 这条的参考图
  002-手机壳/
    prompt.txt
    主图.png
```

按文件夹名排序依次做。以 `_` 或 `.` 开头的文件夹会被跳过。

**2 · 账号 Cookie**
一个账号一段，**中间空一行**隔开。请求头原文 / JSON 数组 / Netscape 三种格式都认，
和你往创作台里导入时用的是同一份东西。

**3 · 提示词前缀**
默认已经填好那句话，会自动加在每条提示词最前面：

> 不要说任何废话，不要让我进行任何二次确定，不要问我任何问题，直接按照你的理解直接生成视频：

**4 · 点「开始」**

然后它自己跑：换账号 → 进视频模式 → 选 2.5 → 开 30 秒 → 选 9:16 → 传这条的图 →
填提示词 → 发送 → 记下会话号 → 下一条。

**5 · 收片**

视频要等几十分钟到两小时才生成好，所以下载是**第二阶段**。
提交完会自动转入收片阶段：挨个回到当初的会话，把**无水印**原片抓出来下载，
文件名就是任务名（`001-口红.mp4`）。没生成好的会每 20 分钟回来再看一次。

想单独收片（比如关了浏览器隔天再来），点「只收片」。

## 它怎么做到那几件事

**30 秒破限**
用的是创作台原版脚本 `dola-15s-dom-request-hook.js`（在 `vendor/`，一行没改）。
原理：写两个 localStorage 开关，再在发请求时把 `ability_type:17` 节点里的
`ability_param.duration` 改写成 30。

**传参考图**
用的是创作台原版脚本 `dola-reference-materials.js`（同样一行没改），
图片走 Dola 自己的上传通道，没有逆向它的接口。

**无水印**
无水印地址是 Dola 接口自己返回的，不是破解出来的：返回里同时有带水印的
（`rendition` 为 `video_gen_watermark_dyn`）和无水印的（`unwatermarked`，
或 `data.original_media_info.main_url`）。扩展钩住网络返回，**挑无水印那条**下载。

**不掉链子**
换账号必须刷新页面，一刷新脚本就重跑、内存全丢。所以进度存在
`chrome.storage.local`、图片存在 IndexedDB，每次页面加载都把状态捞回来接着跑。

## 已验证 / 未验证

**已经实测过的**（在开发机上跑真实代码，17 项全过）：
- 无水印地址识别：能抓到 `original_media_info.main_url` 和 `unwatermarked` 版本，
  **并且确实排除掉带水印的那条**
- 结果判定：额度用尽 / 配额不足 / 掉登录 / 限流 都认得出，成功回复不会被误判成失败
- Cookie 三种格式解析
- 视频地址识别（fplay、.mp4、不把图片当视频）

**没验证的**（开发环境连不上 dola.com）：
- 页面上那几个控件的**精确定位**：模型、时长、比例三个下拉，还有输入框和发送按钮。
  代码里是按原版脚本出现过的属性（`data-input-engine-actionbar-control-key`）推的，
  并做了多级降级，但没在真页面点过。
- 无水印字段在 dola 上的**确切名字**（我是从原版扩展代码里读出来的，没实跑过）。

**所以第一次用，请这样做：**
1. 先只放 **1 条任务 + 1 个账号**，打开面板看日志跑完整一遍。
2. 日志会打印每步命中了哪种方式（比如「模型 → 2.5」「时长 → 30s」），
   哪步不对一眼能看出来。
3. 在 dola 页面按 F12 打开控制台，能看到 `[星辰批量]` 开头的全部日志。
   还可以直接调 `__XCB_DEBUG__.classify('某段文案')` 验证判断逻辑。
4. 确认这一条从提交到下载都通了，再上批量。

## 风险提醒

批量自动提交有被平台风控的可能。两条之间默认等 45～90 秒随机，**别调短**。
账号怎么来的不在本工具范围内——它只负责「给了账号和图，就自动生成 + 自动下载」。
